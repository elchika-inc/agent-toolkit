# 動作検証の実行と資料化

## Overview

動作検証は `verification-documenter` サブエージェントが実行し、**レポートの書き出しは呼び出し元が行う**。
この責務分割は必須であり、省略可能な手順ではない。

**サブエージェントは `Write` でレポートファイルを書けない。** ハーネスがブロックする（brain の `risk-subagent-write-report-blocked.md` / URISK-045）:

```
Subagents should return findings as text, not write report files.
```

サブエージェントは所見をテキストで返すところまでしかできない。**返ってきたテキストを誰もファイルにしなければ、検証結果はチャットとともに消える。**
詳細で完璧に見えるレポートが出力されるので、消えたことに気づきにくい。

## 手順

このスキルの出力は、以下の3つが揃って初めて完成する。1つでも欠けたら未完成。

**1. dispatch する**

`verification-documenter` を Agent ツールで起動する。プロンプトには最低限これを含める:

- 対象（パス / URL / エンドポイント）と**起動方法**（起動できないと列挙のみに降格する）
- 副作用の許容範囲（既定は「非破壊のみ。削除・課金・外部送信は実行しない」）
- 壊してはいけない実データがあればその明示

**2. レポート本体をファイルに書き出す**

サブエージェントの最終応答は `===REPORT_BEGIN===` と `===REPORT_END===` でレポート本体を囲んで返す。
**マーカー行の内側だけ**を `Write` で保存する:

```
<PROJECT_ROOT>/.docs/reviews/<対象slug>/report.md
```

- **プロジェクトが `.docs/` の層を規定している場合はそれに従う**（DOCS_OPS §3 の排他ルール: 二重の保存先を作らない — 監査の死角になるため）。プロジェクト側の検査が `.docs/reviews/` だけを走査していると、別の場所へ書いた証跡は magic bytes 検査も SHA 検査も受けずに素通りする。
- マーカー行そのもの、冒頭の `【呼び出し元へ】` 指示行、末尾の evidence パス一覧は**ファイルに含めない**。
- マーカー間の本文は**要約・省略しない**。そのまま資料になる。
- `PROJECT_ROOT` は `git rev-parse --show-toplevel 2>/dev/null || pwd` で決める。
- マーカーが見当たらない場合（古い定義のサブエージェント等）は、レポート本文と判断できる範囲を全文保存し、その旨をユーザーに伝える。
- evidence はサブエージェントが `Bash` で既に書き出している。

**3. 実体を確認する（検証ゲート）**

```bash
ls -la <PROJECT_ROOT>/.docs/reviews/<対象slug>/
```

`report.md` と `evidence/` の実在を目で確認するまで、検証は完了していない。
「書き出した」という自分の主張を根拠にしない。

## サブエージェントの報告を実体で裏取りする

`verification-documenter` は列挙・実行・判定を1人で行う（builder が自分を採点する構造）。
レポート内の**検証可能な主張は、呼び出し元が独立に確認する**:

| 主張の型 | 裏取りの手段 |
|---|---|
| 「この関数はどこからも呼ばれない」 | `grep -rn <関数名> src/` |
| 「コミット X で検証した」 | `git -C <path> log -1 --format=%H` |
| 「src/ は無改変」 | `git -C <path> status --porcelain` |
| 「ドキュメントに記載がない」 | `grep -c <語> <doc>` |
| 「保存した」 | `ls` |

判定が `⚠️未確認・要人間判断` のケースは、そのままユーザーに提示する。呼び出し元が勝手に合格へ昇格させない。

## Common Mistakes

| 症状 | 何が起きているか |
|---|---|
| レポートがチャットにしか無い | 手順2を飛ばした。次のセッションで検証結果は失われる |
| サブエージェントが「ハーネス制約で書けない」と報告し、そこで終わる | それは正常な挙動。呼び出し元が書けばよい |
| サブエージェントに `Bash` のヒアドキュメントで書かせる | ハーネスの明示的な設計意図に逆らう迂回。採らない |
| レポートを要約して保存した | 再現手順とエビデンスの対応が失われ、資料の価値が消える |
| 「全ケース ✅」で終わっている | 破壊的ケースは `⏭️要人間実行` に退避されているはず。全部緑なら列挙が浅い |

## Real-World Impact

初回の運用で、サブエージェントは検証を完遂しレポート全文を返したが、`report.md` は存在しなかった。
呼び出し元が `ls` で不在に気づいたため資料は救われたが、気づかなければ消えていた。
**動作検証の資料管理エージェントが、資料を残せずに成功報告を返す**という形の false success であり、手順3の検証ゲートはこの実失敗から来ている。
